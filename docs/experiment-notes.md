# Experiment provenance and limitations

## Source and publication changes

기준 자료는 팀 과제의 `Assignment1_Team4 _EDA.ipynb`, `Assignment2.ipynb`, `Final_Project.ipynb`입니다.
파일명을 분석 단계에 맞추고 데이터 경로를 `../data/labeled_data.csv`로 통일했습니다.
로고와 불필요한 노트북 메타데이터를 제거하고 대표 그래프를 분리했습니다.
전처리 데이터의 저장 위치는 `outputs/`로 바꿨습니다. 원 모델·평가 계산은 다시 실행하거나 변경하지 않았습니다.
원본 해시와 변경 범위는 `provenance.json`에 기록되어 있습니다.

노트북은 기존 실행 결과를 보존한 기록입니다. 새 경로·현재 패키지 버전으로 전체 실행이 검증된 결과를 뜻하지 않습니다.
requirements는 직접 의존성 목록이며 원 환경의 잠금 파일은 아닙니다.

## Interpreting performance

최종 노트북의 라벨은 `Y → 1`(정상), `N → 0`(불량)입니다. 기본 sklearn 지표의 양성 클래스는 정상입니다.
기존 설명에서 precision·recall을 불량 탐지 지표처럼 표현한 부분은 이 정의와 맞지 않습니다.
시험셋에서 불량 14개 중 6개를 탐지했으며, 불량 recall은 42.9%입니다.
높은 정상 클래스 F1을 높은 불량 검출률로 해석하지 않습니다.

## Preprocessing and validation limitations

- 원 노트북은 일부 IQR 경계, 평균·표준편차, 인코딩 등을 train/test 분할 전에 계산합니다.
  교차검증 Pipeline의 scaling·SMOTE는 학습 fold 안에서 수행하지만, 앞선 통계 처리까지 완전히 분리된 것은 아닙니다.
  엄밀한 새 성능 평가는 모든 학습형 전처리를 fold 내부로 옮긴 뒤 별도로 실행해야 합니다.
- `Reason`은 검사 후 생성되는 정보입니다. 사전 불량 예측의 입력에서는 명시적으로 제외해야 합니다.
  원 최종 출력에서는 해당 더미 변수들이 비수치형으로 제외되었지만, 패키지 버전에 따른 dtype 변화에 의존하면 안 됩니다.
- 정상 7,925개, 불량 71개로 클래스 불균형이 큽니다. 정상 기준 accuracy/F1만으로 모델을 선택하면
  현장에서 중요한 불량 누락을 충분히 반영하지 못합니다.
- 원 노트북의 일부 문장은 템플릿·학습 과정의 설명을 포함합니다. 실제 구현과 평가는 코드 및 저장 출력과 함께 판단해야 합니다.

개선 실험을 수행할 경우 원래 결과와 구분하여 불량을 양성 클래스로 명시하고 클래스별 지표를 함께 보고하는 것이 적절합니다.
